# HumanWire Universe 工程与实验路线图

> **当前阶段**：Phase 0（思想宣言与协议规范公开 `v0.1.0-rfc`）  
> **更新日期**：2026-11-25

本路线图记录从协议构想到可复现实验、最小可用原型与学术发表的演进步骤。**所有定量结论必须由本仓库公开的可运行脚本亲手跑出并留存完整随机种子与日志后，才会写入实验报告与论文。**

## Phase 1：可复现离散事件仿真基准（`sim-bench`）

目标：用纯 Python 实现透明、可一键复现的多智能体网络仿真器，验证制度设计是否存在隐藏死锁或相变崩溃。

- [ ] **对照与消融实验**：对比无治理开放网络、中心化发分机制、线性权重、以及完整 Universe Mode（剥离本地海关、时间半衰期、平移门槛、动态变形蜜罐、跨模型盲审、双通道墓碑等单模块消融）。
- [ ] **极端压力相变扫描**：测试“潜伏卡特尔 + 女巫拆分”下的治理失守阈值、半衰期过短导致“新节点永不激活”边界，以及高节点流失率下的 P2P 存储存活率曲线。
- [ ] **单位经济学核算**：基于真实公开 API 定价与本地硬件边际功耗，验证紧凑胶囊（`<= 1,200` tokens）相对原始长轨迹的复用盈亏平衡点。

---

## Phase 2：最小可运行原型（`kernel-core` + `universe-node`）

目标：严格遵守零依赖安全边界，写出可实际跨节点运行的轻量核心实现，同时保持与 `Peer Mode`（`humanwire`）的底层兼容。

- [ ] **只读内核与本地协议海关**：零依赖实现 4 份 JSON Schema 校验器、`genesis_hash` 计算、Ed25519 验签、Context Bloat 体积闸门、高危静态载荷扫描及本地替身脱敏。
- [ ] **双通道存储与免疫引擎**：实现 `solution` + `tombstone` 分槽检索、滑动窗口察看期动态变形蜜罐、Commit-Reveal 盲审状态机及翻译为无感采纳回执的信誉账本。
- [ ] **P2P 存储抽检与插件同步**：接入可选 `hyperswarm`/`hypercore` 实现随机字节区段 `Tit-for-Tat` 抽检与懒修复；验证 Nostr NIP-34 热插拔插件同步与人类熔断确认锁。

---

## Phase 3：低预算真实多模型 PoC 评测（`poc-runner`）

目标：控制个人独立研究者可承受预算上限（设置 API 支出硬熔断锁），在真实大模型与容器沙盒上验证核心假设。

- [ ] **跨模型胶囊迁移实测**：在公开编码修复基准上对比强模型提炼胶囊 + 避坑墓碑对开源本地小模型 / 低价云端模型的 `Pass@1`、重试步数与 Token 成本影响。
- [ ] **真实注入与盲审实测**：在公开 Agent 安全测试集上验证本地协议海关拦截率与良性任务效用留存率；测试多家族真实 LLM 盲审小法庭对抗隐蔽语义投毒的表现。
- [ ] **多节点实网测试床**：通过容器 / 微型跨区节点接入公网 Nostr 中继与 Hyperswarm DHT，实测握手吞吐、字节抽检延迟与补丁同步成功率。

---

## Phase 4：学术规范核验与投稿路径

- [ ] **文献零幻觉核验**：编写自动化脚本逐条交叉核验所有外部引用文献的标题、作者、年份与 arXiv/DOI 编号，确保 100% 真实可查。
- [ ] **成果分流投稿**：
  - 原型演示路径：面向多智能体系统演示赛道（Demo Track）提交可运行原型与演示视频；
  - 完整机制 / 安全论文路径：视实验完整度投递 AI / 系统安全主流会议或 Workshop；
  - 预印本与软件期刊：在获得完整可复现代码与实验结果后申请 arXiv 同行背书并提交开源软件期刊（JOSS）。
